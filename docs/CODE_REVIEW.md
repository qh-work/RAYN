# RAYN Weather 代码审查与性能治理

审查日期：2026-08-16  
目标平台：tvOS 27  
重点设备：Apple TV 4K（第二代，A12）

## 2026-08-19 复审摘要

- 原 `SceneViews.swift` 已删除，六类主场景分别进入独立文件；数据模型和 Provider 边界未因视觉重构而改变。
- 新增场景转场、天气刷新、雷达地图就绪和雷达帧提交的系统性能标记，之后可以直接在 A12 真机的 Instruments 中建立冷、热切换基线。
- 每秒更新的底部时间栏、日期标签和服务时间解析改用加锁缓存的格式化器，不再在渲染路径反复创建 `DateFormatter`。
- 当前天气、24 小时、空气质量和日照月相完成 4K 重新排版；所有 24 个小时可聚焦，太阳和月亮可进入详情。
- 设置新增页面排序；旧版本设置解码后会去重并自动补入新页面，不破坏已有开关。
- 玻璃卡片会响应“降低透明度”和“增强对比度”，新增文字保持九种语言完整。

本轮没有降低动画帧率，也没有增加演示数据、启动天气缓存或伪造的月升月落。Open-Meteo 不提供的月升/月落继续明确显示缺失值。

## 结论

本次严重卡顿不是 A12 性能不足，也不是动画帧率过高，而是场景生命周期和雷达图层交换方式错误：

1. 旧转场会让 24 小时图表、10 日材质卡片或雷达地图在同一 4K 帧中重叠布局和合成。
2. 10 日页原来由多张独立材质卡片组成，退出页面时离屏模糊和阴影开销过大。
3. 雷达帧更新会立即刷新当前图层；旧帧被清空、新瓦片尚未到达时就出现闪空和抽搐。
4. 雷达瓦片没有先行准备，慢请求会在播放过程中累积下载和解码压力。
5. 全局方向键处理和 tvOS 焦点系统同时改动页面，自动轮播旧倒计时又不会因手动选择重置，所以雷达标签仍聚焦时内容可能被推进到空气质量。

这些问题会让主线程布局、MapKit 初始化、网络回调、PNG 解码和 4K 材质合成同时发生。A12 上表现为转场无响应或抖动；更新款芯片可能只表现为短暂掉帧，因此不能以新设备体验推断第二代 Apple TV 的表现。

## 已完成的性能修复

| 位置 | 修改 | 预期作用 |
| --- | --- | --- |
| `BroadcastView` | 先淡出并释放旧场景，再在不可见状态创建新场景，完成首轮布局后淡入 | 保证两个重型页面不会同时参与 4K 合成 |
| `DailyForecastScene` | 10 张独立材质卡改为单一玻璃面板中的常驻 `VStack` 列表 | 显著减少材质、阴影和布局节点；避免惰性回收造成焦点丢失，同时支持上下滚动 |
| `DailyForecastScene` | 使用 `defaultFocus`、焦点作用域和焦点恢复 | 第一行默认聚焦，10 天均可选择、确认、查看详情和返回 |
| `RadarScene` | 页面先完成交接，约 0.28 秒后再创建地图 | 避免 MapKit 冷启动与上一页退出竞争 |
| `RadarTileMapView.Coordinator` | 地图、区域和地点标注常驻 | 消除每帧地图状态重建 |
| `RadarTileOverlay` | 下一帧先预取真实瓦片，成功后叠放到旧帧之上，再移除旧帧 | 不再使用 `reloadData()`，消除空白帧和图层抽搐 |
| `RadarTileOverlay` | 新请求到来时取消未完成的旧帧预取 | 避免过期请求堆积和无效解码 |
| `RadarTileOverlay` | 32 MB 内存瓦片缓存，禁止磁盘缓存 | 循环播放可复用相同真实瓦片，不使用跨启动旧数据 |
| `DynamicSkyView` | 保持系统显示节奏；仅在用户开启“减少动态效果”时暂停 | 不以降低视觉帧率掩盖地图重复工作的缺陷 |
| `AppState` | 自动轮播改为默认关闭；启用后每次用户操作都重新计时 | 手动选中雷达后不会突然跳到空气质量 |
| `BroadcastView` | 方向键只交给 tvOS 焦点系统，不再暗中切页 | 消除标签焦点与实际内容不一致 |
| `SettingsView` | 设置改为可返回的全屏界面，顶部焦点区引导到齿轮 | 设置按钮可达、可打开，轮播可明确开关 |

内存缓存的键是包含雷达帧时间戳的完整瓦片 URL，因此只会复用完全相同的真实帧；应用退出后自动清空。它不属于启动缓存，也不会在网络失败时生成或展示演示回波。

## 验收标准

真机验收应从 10 日预报页反复切换到雷达页，不只从轻量页面进入：

- 按下确认后立即出现视觉反馈，旧场景释放与新场景首轮布局串行完成。
- 地图在约 0.28 秒后开始初始化，不阻塞场景转场。
- 不应出现可感知的数秒界面冻结或遥控器输入丢失。
- 自动播放期间地图中心和地点标记保持稳定，只有雷达回波发生变化。
- 雷达标签被确认后不得出现空气质量内容；自动轮播启用时，手动操作必须重新开始停留计时。
- 循环播放后内存不会随循环次数持续增长；瓦片内存缓存上限为 32 MB。
- 网络慢时允许瓦片逐步出现，但页面控制区必须保持可操作，且不得展示伪造回波。

自动化回归现已由 `RAYNUITests` 使用 `XCUIRemote` 覆盖：24 小时 → 10 天 → 雷达、10 天向下选择第 4 天并打开/返回详情、设置按钮打开/关闭、内陆日月页面，以及 18 次跨场景往返压力测试。2026-08-16 的 tvOS 27 模拟器结果为 5 项 UI 测试和 25 项单元测试全部通过；A12 实机的十日详情、跨场景压力和设置路径 3 项测试也全部通过。

建议使用 Instruments 的 Time Profiler、Core Animation 和 Network 模板各记录一次 A12 真机过程。记录时至少重复 10 次“10 日预报 → 雷达 → 10 日预报”，区分首次 MapKit 冷启动和后续热切换。

## 已完成的开源架构重构

- `ProviderContracts.swift` 只保留稳定协议、归因和组合模型。
- `RefreshCoordinator.swift` 只负责编排，不再与供应商 DTO 混在一起。
- Open-Meteo 天气、空气质量、海况、地址搜索及 RainViewer 雷达各有独立文件；替换一个服务不需要修改其他实现。
- 所有网络型 Provider 都从初始化器接收 `HTTPClient`，正式环境默认使用 `URLSessionHTTPClient`，测试可注入静态或故障传输。
- 五类来源统一由 `ProviderConfiguration.swift` 选择；主界面和动画只读取 `WeatherSnapshot`。

## 仍需重构的代码问题

### 已解决：单一场景文件过大

原约 3,000 行的 `SceneViews.swift` 已拆成以下可独立定位的模块：

建议按功能拆分：

```text
Features/Broadcast/
├── CurrentWeatherScene.swift
├── HourlyForecastScene.swift
├── DailyForecastScene.swift
├── RadarScene.swift
├── AirQualityScene.swift
└── AstronomyScene.swift
```

首轮拆分先保留同一场景内部的紧密实现，避免为了文件数量制造跨文件私有状态。`AstronomyScene.swift` 和 `RadarScene.swift` 仍是下一轮候选，但只应在太阳、月相或地图桥接形成可独立测试边界时继续拆分。

### P1：缺少真机性能门限自动化

`RAYNUITests` 已覆盖关键遥控器焦点路径和页面交接，但模拟器无法代表 A12 上的 MapKit 瓦片解码与 4K 合成成本。发布流程仍应增加 A12 真机的 hang、长帧和峰值内存门限，并继续验证雷达播放、暂停、前后帧按钮。

### P1：WeatherKit 测试依赖系统认证服务

现有 WeatherKit 测试会尝试连接系统认证服务，再把认证失败视为预期结果。它在无对应服务的模拟器中会产生 XPC 错误日志，也可能受系统版本和签名状态影响。

建议在 `AppleWeatherKitProvider` 前增加可注入的 WeatherKit 客户端协议。单元测试使用明确返回错误的客户端；只有单独的集成测试才访问系统 WeatherKit。

### 已解决：格式化器在渲染路径创建

`WeatherDateFormatterCache` 现在按语言、时区和格式模板复用实例，并在同一把锁内完成格式化。Provider 的 ISO 时间解析同样复用格式化器。后续新增日期显示应继续走该入口，不在 `body` 或每秒时间线上直接创建格式化器。

### P2：`AppState` 职责偏多

`AppState.swift` 约 405 行，同时管理定位、设置持久化、场景导航、自动轮播、刷新重试和页面控制可见性。

建议逐步提取：

- `SettingsStore`：设置和地址持久化。
- `BroadcastNavigator`：场景顺序、隐藏页和暂停状态。
- `WeatherSession`：刷新、重试和数据状态。

`AppState` 最终只组合这些对象并向 SwiftUI 发布状态。

### P2：并发检查仍为最低级别

项目使用 Swift 5 且 `SWIFT_STRICT_CONCURRENCY = minimal`。建议先在 CI 增加 Swift 6 严格并发警告构建，修复跨线程模型和回调标注后，再单独切换语言模式；不要把并发迁移与 UI 重构放在同一个提交中。

## 后续性能路线

1. 先在 A12 真机建立冷启动和热切换基线。
2. 若仍有长帧，优先检查 MapKit 首次初始化和材质卡片离屏渲染，不先降低数据真实性。
3. 天气动画保持系统显示节奏；若未来增加效果档位，只能由用户主动选择或辅助功能控制，不能因进入雷达页自动降帧。
4. 雷达供应商适配层继续保持 URL 模板与 UI 解耦，方便替换更高精度服务。
5. 发布前同时验证 1080p、4K、HDR 电视和投影模式，尤其检查高亮面积、焦点可见性和文字安全区。

## 本次不变的产品边界

- 不使用演示天气、伪造回波或启动旧快照填充正式界面。
- 网络失败时明确显示不可用，不把缺失值写成零。
- 雷达内存缓存只降低当前播放循环的重复工作，不改变数据时间戳和来源。
- 天气主界面不显示开发注释、Provider 名称或“未使用大模型”等实现说明；服务许可强制要求的名称仅出现在“关于与归因”页。
