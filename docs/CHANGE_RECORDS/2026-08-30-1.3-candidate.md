## Changes and reasoning

- Radar used separate map/prefetch request paths and waited for a ring before handoff. The candidate removes the ring, shares URL-keyed flights and a 32 MB compressed-data cache, caps active downloads at four, and handles Retry-After. This is a request/network policy, **not a display-frame-rate reduction**.
- The last drawn overlay stays until a pending overlay reports a drawing pass after receiving real tile data. Superseded pending overlays are cancelled; at most two layers remain. A 20-second UI timeout exposes retry without inventing successful playback. Partial-tile visual behavior still needs physical-device verification.
- Scene changes now use animation completion and generation checks instead of fixed handoff sleeps. Inactive scenes suspend animation and refresh work; the minute-only clock no longer redraws each second.
- City changes reset refresh isolation and cancel obsolete work. Foreign-city fallback data is rejected. Startup and failed forecast refreshes do not return stored or fixture weather, while successful forecast-only refreshes preserve supplemental models.
- NWS official alerts have explicit availability and stable IDs. Invalid official payloads cannot silently become all-clear. NOAA WMS frames are derived only from advertised timestamps, with provider-owned legends and an all-source RainViewer fallback.
- Home spacing and clothing typography are less compressed. Solar details have a larger chart and correct day-length handling; moon highlights are softer. Daylight bars share an absolute scale rather than exaggerating small daily changes.
- WeatherKit has a bring-your-own configuration and runtime attribution; no account, team, entitlement credentials or private source data are embedded.
